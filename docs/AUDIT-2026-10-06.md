## Tekshirish doirasi

- Uch tildagi navigatsiya, loyiha sahifalari, blog, profillar, aloqa va ustaxona.
- Mobil ko‘rinish, klaviatura boshqaruvi, mavzu almashtirish, qidiruv, drawing board va fon harakatining to‘xtashi.
- Metadata, canonical va tarjima havolalari, sitemap, RSS, 404 va maxfiy preview.
- Kontent yaratish, tahrirlash, tiklash, tarjima, preview, tasdiqlash, nashr va nashrdan olish.
- Bot egasini tekshirish, guruhdan yuborilgan amallarni rad qilish, eskirgan tugmalar va qayta kelgan webhook’lar.
- Kanal matni/media, havola tugmalari, preview, tahrir, pin, o‘chirish, kanal nomi va tavsifi.
- Telegram yoki baza uzilishidan keyingi noaniq natijalar, bir martalik yuborish va egasi orqali tiklash.
- SQL tranzaksiyalari, yozuv/seans versiyalari, RLS, jadval va funksiya ruxsatlari, dependency va build tekshiruvlari.

Kanalga test xabarlari yuborilmadi. Nashr/tahrir/o‘chirish sinovlari mahalliy Telegram provayderi va PGlite bazasida bajariladi. Jonli tekshiruv faqat sayt, bot ulanishi va administrator ruxsatlarini o‘qiydi.

## Tashqi cheklovlar

GitHub Actions’ning amaldagi [run](https://github.com/sardorcodev/sardorcodevuz/actions/runs/37427315790) hisobning billing bloklanishi sabab boshlanmagan: “The job was not started because your account is locked due to a billing issue.” Bu kod xatosi emas; hisob egasi [billing sozlamalarida](https://github.com/settings/billing) tekshirishi kerak. Lokal sinov va Vercel build natijalari alohida qayd etiladi.

`npm audit` rivojlantirish vositalarida [braces GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) va uning to‘rtta bog‘liq paketini ko‘rsatadi. 2026-10-06 kuni `braces` uchun tuzatilgan reliz mavjud emas. U `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch` orqali keladi; production dependency auditida mavjud emas. Ushbu repository ESLint’ga foydalanuvchi yuborgan glob bermaydi. Next.js 16 sozlamasini nomos eski versiyaga tushirish orqali ogohlantirish yashirilmadi.

Supabase’ning 7 ta [“RLS Enabled No Policy”](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) INFO yozuvi yopiq server jadvallari uchun kutilgan: `anon` va `authenticated` o‘qiy olmaydi, serverning `service_role` kaliti boshqaradi. Yangi kanal indekslarining [“Unused Index”](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index) INFO holati hozircha ishlatilmagan yangi jadvallar uchun tabiiy; zarur indekslar saqlanadi.

## Tekshiruv natijalari

- Format, ESLint va TypeScript tekshiruvlari o‘tdi.
- 51 ta unit/SQL tekshiruvi tasdiqlandi. Vaqt o‘tishini simulyatsiya qiluvchi ikkita yangi SQL fixture immutable timestamp himoyasiga moslashtirilib, alohida qayta sinovdan o‘tkazildi.
- Brauzerda 79 ta holat qamrab olindi: to‘liq dastlabki 73 sinovdan 72 tasi o‘tdi, uzun responsiv sinov vaqt chegarasiga urildi. Uch tildagi responsiv sinovlar ekran o‘lchamiga ajratilib, barcha 9 tasi qayta o‘tdi; qolgan 70 ta holat dastlabki to‘liq tekshiruvda o‘tgan.
- CMS HTTP → SQL → brauzer integratsiyasi va kengaytirilgan kanal HTTP → SQL → Telegram provayderi oqimi o‘tdi. Maxfiy preview, Markdown/XSS, nashr/nashrdan olish, o‘zbekcha qidiruv va botdagi qayta kelgan webhook tekshirildi.
- Production build tekshirildi. Kanalning yakuniy integratsiyasi yangilangan barcha migratsiyalar bilan qayta build qilindi.
- Jonli sitemapdagi 34 sahifa va uch tildagi RSS tekshirildi: javoblar, til, canonical, yagona H1 va xavfsizlik sarlavhalari to‘g‘ri.
- `npm audit --omit=dev` production dependency’larda 0 ta zaiflik ko‘rsatdi. Tuzatilmagan development advisory yuqorida ochiq qayd etilgan.
- Ikki yangi migratsiya jonli Supabase’ga kontentni o‘chirmasdan qo‘llandi; funksiya ruxsatlari server uchun yopiq holda saqlandi.
